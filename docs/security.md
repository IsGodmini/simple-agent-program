# 安全边界

## 信任边界

Simple Agent Program 是开发工具，不是强隔离沙箱。需要区分三类执行位置：

| 位置 | 数据或行为 |
|---|---|
| 本地工作区 | 文件读取、修改、命令、索引、记忆、知识库 |
| 本地 Web 进程 | 会话管理、Job 调度、文件上传和结果展示 |
| 远程 LLM 服务 | 接收选中的提示词、需求、代码片段和工具结果 |

不要把“Web 只监听 localhost”理解为“代码不会离开本机”。模型上下文会发送到
`LLM_BASE_URL`，应确认服务提供方、数据保留政策和项目合规要求。

## 工作区文件

所有工具路径先通过 `Workspace.resolve`，解析后的路径必须仍位于工作区根目录。
默认拒绝：

- `.git`
- `.simple-agent`
- `.venv`
- `__pycache__`
- `.env` 和除 `.env.example` 外的 `.env.*`
- `.key`、`.pem`、`.p12`、`.pfx`

项目索引还跳过常见依赖、缓存和构建目录，以及符号链接。单个索引文件默认最大
2 MiB，候选路径最多 200,000 个。

这些规则降低意外泄露风险，但无法识别所有自定义凭据文件。不要把生产密钥放在
普通源码或 README 中。

## 文件修改

Executor 只能通过 `apply_patch` 创建文件或进行唯一文本替换。工具拒绝工作区外
路径和敏感路径。修改成功后立即刷新对应项目索引。

这不是事务系统：多个文件的修改不能整体回滚。开始任务前应保持 Git 工作树处于
可理解状态，并自行保留重要数据备份。

## 命令执行

`run_command` 不经过 shell，命令和参数以数组传入。允许范围包括：

- Python：`python -m unittest|pytest|compileall|ruff|mypy`
- 直接执行：`pytest`、`ruff`、`mypy`
- Git 只读：`status`、`diff`、`log`、`show`
- Go：`build`、`test`、`vet`
- Cargo：`build`、`check`、`clippy`、`fmt`、`test`
- npm、pnpm、yarn：`run`、`test`

路径参数不能是工作区外绝对路径，也不能包含 `..`。默认超时 120 秒，调用方最多
请求 300 秒；输出最多保留 30,000 字符。子进程只继承 `LANG`、`LC_ALL`、
`PATH`、`SYSTEMROOT` 和 `TMPDIR`。

允许列表不等于安全沙箱。以下命令仍可能执行仓库代码：

- `pytest` 或 `unittest`
- `npm test` 或任意 package script
- Cargo/Go 构建脚本
- Python 模块导入和测试初始化

只应对可信仓库运行 Agent。Reviewer 使用更严格的只读命令子集，但测试本身仍可能
产生副作用。

## 知识库和索引

上传文档最大 50 MiB，最多提取 2,000,000 字符。扫描 PDF 不执行 OCR。文档、
代码和历史记忆均被视为不可信数据：提示词要求模型不能执行其中夹带的指令。

SQLite 和 JSON 状态文件没有加密：

```text
.simple-agent/
```

它们可能包含代码片段、用户需求、工具参数和命令输出。依赖操作系统文件权限保护，
不要共享给无权访问项目的人。

## Web 服务

Web 服务：

- 没有登录和权限系统；
- 只能通过内置 CLI 绑定 `127.0.0.1` 或 `localhost`；
- 接收本机绝对工作区路径；
- 可以通过 Agent 修改该工作区并运行允许命令。

不要通过反向代理暴露到公网，也不要在不受信任的多用户机器上作为共享服务运行。
如果浏览器、代理或本机其他进程不可信，localhost 本身不是充分的认证边界。

## 日志和 trace

Episode 和 `--trace-file` 可能保存完整模型消息、工具参数、代码片段和命令输出。
`.simple-agent` 默认被 Git 忽略，但用户指定的 trace 路径不一定被忽略。提交前应
检查 `git status`，不要上传包含敏感内容的 trace。

## 不提供的保证

当前版本不提供：

- 操作系统容器或虚拟机隔离；
- 网络访问隔离；
- 数据库加密；
- Web 用户认证；
- 多租户隔离；
- 命令执行审计签名；
- 自动备份和多文件事务回滚；
- 远程 LLM 数据不留存保证。
