# 上下文与记忆

## 一次模型请求的组成

普通 Planner、Executor 或 Reviewer 请求按以下逻辑构建：

```text
1. 当前角色提示词
2. 需求级模型调用预算说明
3. 原始用户需求锚点
4. 当前会话和相关场景记忆（存在时）
5. 相关知识库片段（命中时）
6. 项目概览和相关代码片段
7. 当前 Agent 输入或结构化子任务
8. 当前 Agent 尚未被压缩的模型/工具交互
9. 本轮临时目的驱动提醒
10. tools JSON Schema（作为请求独立字段）
```

最终综合使用专用 Synthesizer 提示词、原始需求、已完成步骤、评审结果和同一个任务
提醒。预算或停滞收尾会使用禁止工具的最终回答提示。

## 原始需求锚点

`ContextBuilder` 总会添加当前用户需求，即使没有历史记忆、知识库命中或项目索引
结果。锚点最多保存 20,000 字符，并标记是否截断。

每次调用 LLM 前，`Agent` 还会临时追加：

- 原始用户需求，最多 8,000 字符；
- 当前 Agent 范围，最多 4,000 字符；
- 当前调用轮次；
- 目的驱动约束。

临时提醒要求工具必须推进实现决策、代码修改或验证，证据足够时立即结束。提醒
不会写回长期消息列表，所以不会随循环次数重复累积。

## 会话记忆

自动记忆包括：

- 当前会话标题和滚动摘要；
- 当前会话最近需求摘要；
- 当前会话中与新需求相关的摘要；
- 同一工作区其他会话中相关且已完成的场景记忆摘要。

跨会话自动召回要求至少两个检索词项重合。失败需求仍保存 Episode，但不会自动
注入其他会话。

需求摘要记录结果、修改文件、验证命令、可信状态和所属会话。完整工具过程保存在
Episode 中，只有显式调用 `search_memory` 或 `read_episode` 才会读取。

## 知识库上下文

知识库默认最多返回 5 个相关片段，正文预算约 10,000 字符。每个片段带有：

```text
knowledge:<document-id>#chunk-<n>
```

知识库文本属于不可信项目数据，不能覆盖系统指令或当前用户需求。

## 项目索引上下文

在项目索引消息前，系统会先增量刷新 Neo4j 项目图谱并检索最多 6 个相关文件功能
档案，同时提供少量一层关系和紧凑图谱概览，消息上限约 12,000 字符。文件档案由
LLM 生成并以内容哈希控制更新。引用格式为 `graph:<path>`。

如果 Neo4j 返回相关文件档案，系统不会自动检索或注入代码正文；项目索引消息只保留
紧凑概览。只有图谱没有匹配结果或不可用时，才检索最多 6 个相关代码块：

- 相关代码正文预算约 8,000 字符；
- 整个项目索引消息最多约 14,000 字符；
- 项目概览默认树深度为 2，最多 120 个条目；
- 引用格式为 `project:<path>#L<start>-L<end>`。

回答项目结构、关系和文件职责时可以直接使用 Neo4j 档案。索引用于回退定位，不替代
当前文件；只有需要检查或修改具体实现时才使用 `read_file` 核对磁盘内容。

代码块、知识片段、文件档案和场景记忆默认保留关键词排序；配置 Embedding 后还会
查询 Chroma，并使用 RRF 融合两个独立排名。向量内容不直接扩大上下文预算，只改变
候选片段排序。

## 同一需求内部

同一个 Agent 的后续调用会看到前面的 assistant 工具调用和 tool 结果，以便记住
刚刚读取、修改和验证的内容。

Planner、不同 Executor 和 Reviewer 不共享完整内部对话。它们通过以下结构化数据
衔接：

- 原始需求；
- 计划和当前步骤；
- 已完成步骤的紧凑结果；
- 修改和测试证据；
- Reviewer 的结构化结论。

这样可以避免复杂需求把所有子 Agent 的原始工具历史重复发送。

## 不同需求之间

新需求不会加载旧需求的完整模型/工具对话。默认只加载需求摘要、会话摘要和相关
跨会话场景记忆。需要细节时再读取 Episode。

因此隔离规则是：

```text
同一 Agent 循环：保留近期完整交互
不同子 Agent：传递结构化结果
同一会话不同需求：传递摘要
同一工作区不同会话：按相关性共享记忆
不同工作区：完全隔离
```

## Token 估算和压缩

默认配置：

```env
LLM_CONTEXT_WINDOW=128000
LLM_MAX_INPUT_TOKENS=96000
LLM_MAX_OUTPUT_TOKENS=16000
AGENT_COMPACT_AT_TOKENS=80000
```

程序使用保守的 UTF-8 长度估算 Token。达到压缩阈值后，从最早的完整
`assistant tool_calls + tool results` 交互块开始删除，保留：

- 初始系统消息；
- 原始任务和跨需求上下文；
- 最新工具交互；
- 当前目的驱动提醒。

若删除旧交互后仍超过输入上限，程序在本地抛出上下文限制错误，不发送超限请求。
